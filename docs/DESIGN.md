# 聚焦搜索（SpotlightWin）设计文档

版本 0.2 · 2026-10

## 1. 目标

在 Windows 上复刻 macOS 聚焦搜索（Spotlight）的核心体验：

| 需求 | 第一版的做法 |
| --- | --- |
| 随时唤起 | 全局快捷键（默认 `Ctrl+Space`），窗口出现在屏幕上方居中，失焦自动隐藏 |
| 快 | 预先建好本地索引，搜索只查索引；9.8 万个文件的索引上，热查询 6–27 毫秒 |
| 低能耗 | 索引线程以 Windows「后台模式」+ EcoQoS 运行；只在文件变化时增量更新；用电池时暂停读取文档内容 |
| 找文件名 | 文件名分词 + 前缀、子串、首字母（`vsc` → Visual Studio Code）匹配 |
| 找文档里的文字 | 提取 PDF、Word、Excel、PowerPoint、纯文本/代码/Markdown/HTML 的正文，建立全文索引 |
| 中文 | 自研中日韩二元分词，支持任意长度的中文子串搜索，兼容 GBK 编码的旧文本文件 |
| 推荐准确 | 多信号打分：名称匹配程度、你过去对相同输入的选择、打开频率与新近度、类型（应用优先）、全文相关度（BM25）、修改时间、路径深度 |
| 计算器 | 输入 `12*(3+4)` 直接显示结果，回车复制 |

## 2. 技术选型

**C# / .NET 10 + Avalonia 11 + SQLite FTS5 + PdfPig**

- **.NET 10（LTS）**：文件系统 API、P/Invoke 调用 Win32 都很方便；可以发布成单个自包含 exe，用户不用另装运行库。
- **Avalonia 而不是 WPF/WinUI**：渲染效果现代（亚克力半透明、圆角、深浅色自动切换），并且整个项目在任何系统上都能编译和跑测试；界面截图也能离屏渲染出来做检查。WPF 只能在 Windows 上构建，WinUI 3 打包和部署更重。
- **SQLite FTS5 自建索引，而不是直接查 Windows Search**：Windows 自带索引默认不读 PDF 正文（需要另装 IFilter），中文分词效果和排序都不可控，也无法加入「学习你的选择」这类信号。自建索引放在一个文件里（`%AppData%\SpotlightWin\index.db`），可以随时删掉重建。
- **PdfPig**：纯托管代码的 PDF 文字提取库，不依赖 Adobe 或系统 IFilter。
- Office 文档（docx/xlsx/pptx/odt…）本质是 zip + XML，直接解析，不需要安装 Office。

## 3. 架构

```
┌──────────────────────────── SpotlightWin.exe ────────────────────────────┐
│                                                                          │
│  热键线程 ──WM_HOTKEY──▶ UI 线程（Avalonia）                               │
│  (RegisterHotKey)         SearchWindow：输入框 / 结果列表 / 预览           │
│                               │  每次输入（40ms 防抖）                     │
│                               ▼                                          │
│                          SearchEngine ──只读连接──┐                       │
│                                                   ▼                      │
│                                        index.db（SQLite, WAL）            │
│                                                   ▲                      │
│  后台索引线程（低优先级 + EcoQoS）                  │写连接                 │
│    Indexer：首次全量扫描 → NTFS 变更日志（USN）增量 → 内容提取队列         │
│    ContentExtractors：PDF / OpenXML / HTML / 纯文本(UTF-8/UTF-16/GBK)     │
└──────────────────────────────────────────────────────────────────────────┘
```

| 项目 | 内容 |
| --- | --- |
| `src/Spotlight.Core` | 跨平台核心：设置、分词、索引存储、索引器、内容提取、搜索与排序、计算器 |
| `src/Spotlight.App` | Windows 界面：搜索窗口、全局热键、托盘菜单、系统图标、开机启动、单实例 |

| `tools/Screenshot` | 离屏渲染搜索窗口为 PNG |

## 4. 索引

### 4.1 存储结构（`index.db`）

| 表 | 作用 |
| --- | --- |
| `files` | 每个文件/文件夹一行：路径、显示名、扩展名、类型、大小、修改时间、扫描代数 `gen`、内容状态、打开次数和最近打开时间 |
| `names_fts` | FTS5，文件名分词后的 token |
| `content_fts` | FTS5，文档正文分词后的 token |
| `texts` | Brotli 压缩的正文原文，只用于显示结果摘要 |
| `picks` | （输入内容, 文件）→ 选择次数，用于学习排序 |

两个 FTS 表都是 contentless（不重复存储正文），配合 `contentless_delete=1` 支持删除。正文原文用 Brotli 压缩后单独存放。

### 4.2 中文分词

SQLite 自带的 `unicode61` 分词器会把一整串汉字当成一个词，导致中文根本搜不到。做法是在写入前把每段连续的中日韩字符改写成重叠二元组，再加上末尾单字：

```
合同条款  →  合同 同条 条款 款
```

查询时：

- 两个字及以上：拆成二元组短语查询，例如 `合同条款` → `"合同 同条 条款"`，因此任意长度的中文子串都能精确命中；
- 单个字：前缀查询 `"合"*`，匹配所有以它开头的二元组；
- 英文/数字：前缀查询，`rep` 能找到 `report`；文件名还会按驼峰和字母数字边界拆分，`AnnualReport2024` 可以用 `report` 或 `2024` 找到；
- 汉字之间的换行和空格会被忽略，因为 PDF 和硬换行的文本经常把一句话断开。

### 4.3 扫描与增量更新

1. **首次/启动时全量扫描**：遍历开始菜单（用于启动应用）、用户文件夹（桌面、文档、下载、图片、音乐、视频、OneDrive）以及除系统盘以外的所有本地磁盘（D:\、E:\ …）。每次扫描有一个新的代数 `gen`；未变化的文件只更新 `gen`，扫描结束后删除代数过旧的行（即已被删除的文件）。每 2000 条提交一次事务。
2. **增量（NTFS 盘）**：和 Everything 一样读 NTFS 变更日志（USN 日志），每秒读一次，从上次读到的位置接着读。用的是 Windows 10 起普通用户也能调用的 `FSCTL_READ_UNPRIVILEGED_USN_JOURNAL`，不需要管理员权限；代价是记录里没有文件名，只有文件 ID 和所在文件夹的 ID，所以：
   - 爬取时用 `GetFileInformationByHandleEx(FileIdBothDirectoryInfo)` 列目录，一次拿到名称、大小、时间、属性和文件 ID，每行都存下文件 ID（`files.fid`）；
   - 一条记录先查「这个文件 ID 或它所在文件夹的 ID 在不在索引里」（两次索引查询），都不在就跳过（AppData、浏览器缓存这类 C 盘上大部分变化），在的话用 `OpenFileById` 打开得到现在的路径和属性；打不开就是已删除，按文件 ID 找到那一行删掉；路径变了就是改名或移动；新建或移入的文件夹整棵扫描；
   - 每个盘读到的位置（日志 ID + USN）存在 `meta` 表里。程序关闭、待机、重启期间的变化，下次启动从这个位置补上，几秒完成，不再全盘扫描；只有第一次、搜索位置或过滤条件变了、或者日志已经覆盖掉上次的位置时才重新扫描该盘。
3. **增量（非 NTFS 盘）**：U 盘（FAT/exFAT）、网络盘没有变更日志，仍然是启动时扫描 + 每个根目录一个 `FileSystemWatcher`，事件去重后防抖 2 秒再处理；监视缓冲区溢出时自动重扫该根目录。
4. **排除**：`node_modules`、`.git`、`$RECYCLE.BIN`、`Windows`、`Program Files` 等目录名，设置里取消勾选的文件类型和扩展名，隐藏和系统文件，用户在设置里列出的路径；不跟随符号链接/目录联接，避免死循环。
5. **内容提取队列**：只处理「支持的类型 且 大小在上限内 且 修改时间变了」的文件，新修改的优先。有人在用电脑（2 分钟内动过键盘鼠标）时只用一个后台线程，每读完一个文档休息它所用时间的 3 倍（0.3–5 秒），休息期间照常处理文件变化；没人用且接电源时才多线程加速。PDF 逐页读取：坏页跳过，时间用完（1 分钟 + 每 MB 1 秒，最多 15 分钟）时保留已读的页；每个文件最多 500 万字符。没读全或没读到文字的原因会记下来，托盘菜单「检查某个文件为什么搜不到」可以直接看到。

### 4.4 低能耗措施

- 索引线程调用 `SetThreadPriority(THREAD_MODE_BACKGROUND_BEGIN)`：CPU、磁盘 I/O、内存页优先级都降到最低，前台程序几乎感觉不到。
- 同一线程开启 EcoQoS（`ThreadPowerThrottling`），Windows 11 会把它放到能效核、低频率上运行。
- 笔记本用电池时暂停读取文档内容，文件名照常更新；接上电源后自动继续（每分钟检查一次）。
- OneDrive「仅在线」占位文件只索引名字，不读取内容，避免触发下载。
- 空闲时线程阻塞在事件上，不轮询；SQLite 页缓存限制在 4 MB。

### 4.5 待机内存

一天只用几次，所以待机时尽量把内存还给系统：

- 搜索窗口隐藏 5 秒后、以及索引器追上磁盘变化进入空闲时：压缩托管堆（激进模式 GC）、释放 SQLite 缓存（`PRAGMA shrink_memory`）、清空进程工作集（`EmptyWorkingSet`）。下次打开时按需换回，只需几毫秒。
- 用软件渲染代替 GPU（ANGLE/Direct3D）：这个小窗口不需要显卡上下文，省下几十 MB。
- 运行时开启 `GC.ConserveMemory`，更倾向小堆而不是 GC 吞吐。

## 5. 搜索与排序

一次查询的流程：

1. 若输入是算式，直接返回计算结果。
2. **名称候选**：`names_fts` 匹配（最多 3000 条）+ 整个文件名的前缀（走 B 树索引，保证短输入也能找到 `a.txt`）+ 候选不足 50 条时补充子串匹配（`port` 找到 `myreport`）。
3. **全文候选**：输入至少两个字符时，`content_fts` 按 BM25 取前 80 条。
4. 在内存中给每个候选打分，取前 N 条，为全文命中生成摘要。

打分（分值越高越靠前）：

| 信号 | 分值 |
| --- | --- |
| 名称完全相同 | 1000 |
| 名称以输入开头 | 800–900 |
| 某个词以输入开头 | 650–750 |
| 首字母缩写匹配 | 600–650 |
| 名称包含输入 | 520–600 |
| 仅正文命中 | 最高 320，按 BM25 名次递减 |
| 名称和正文都命中 | 名称分 + 正文分 × 0.35 |
| 以前对相同或更短输入选过它 | +220 × log2(1+次数)，最多 +450 |
| 打开频率 × 新近度（半衰期 14 天） | 最多 +300 |
| 类型 | 应用 +260，文档类 +40，文件夹 +25；卸载程序 −400 |
| 7 天内修改 / 30 天内修改 | +40 / +20 |
| 路径深度超过 4 层 | 每层 −6，最多 −60 |

「学习」的效果：比如你输入 `pro` 后选了 `project-beta`，下次再输入 `pro`（或者 `p`、`pr`）它就会排在最前面。这是测试 `LearnsFromPicks` 覆盖的行为。

## 6. 界面与交互

- `Ctrl+Space` 唤起/隐藏；窗口失焦自动隐藏；再次运行 exe 也会唤起已在运行的实例。
- `↑ ↓` 选择，`Enter` 打开，`Ctrl+Enter` 在资源管理器中定位，`Ctrl+Shift+C` 复制路径，`Esc` 先清空再关闭。
- 左侧结果列表显示系统图标、名称和所在文件夹（仅正文命中时显示摘要）；右侧预览显示大小、修改时间、路径和高亮的正文摘要。
- 托盘菜单：打开搜索、重新扫描、开机自动启动、编辑设置、退出。
- 深浅色跟随系统，Windows 11 上为亚克力半透明背景。

## 7. 设置

托盘菜单 →「设置…」打开设置界面，保存后立即生效（重新注册快捷键并重新扫描）。设置保存在 `%AppData%\SpotlightWin\settings.json`：

| 键 | 默认值 | 说明 |
| --- | --- | --- |
| `Hotkey` | `Ctrl+Space` | 例如 `Ctrl+Shift+Space`、`Win+F2` |
| `Roots` | 空 | 要索引的文件夹；为空时用默认的用户文件夹 + 所有数据盘 |
| `ExcludedDirNames` | `node_modules` 等 | 在任何位置都跳过的文件夹名 |
| `ExcludedPaths` | 空 | 跳过的具体路径 |
| `ExcludedKinds` | 空 | 不索引的文件类型，如 `Text`、`Image` |
| `ExcludedExtensions` | 空 | 不索引的扩展名，如 `.txt` |
| `IndexContents` | `true` | 是否索引文档正文 |
| `MaxContentFileSizeMB` / `MaxPdfFileSizeMB` | 20 / 300 | 超过此大小只索引文件名 |
| `MaxContentChars` | 5000000 | 每个文档最多保留的字符数 |
| `PauseContentIndexingOnBattery` | `true` | 用电池时暂停读取正文 |
| `IndexHiddenFiles` | `false` | 是否索引隐藏文件 |
| `MaxResults` | 30 | 最多显示的结果数 |


## 8. 已验证的部分与已知限制

在云端 Linux 环境中验证过：

- 核心引擎 32 个测试全部通过，包括中文名称与正文、GBK 文本、PDF、docx、增删改的增量更新、学习排序、文件监视；
- 在 97,905 个文件（41,716 个含正文）上建索引用时 84 秒，索引文件 252 MB，热查询 6–27 毫秒；
- Windows 版 exe 交叉编译成功，界面通过离屏渲染检查。

**尚未在真机 Windows 上运行过**。全局热键、托盘、系统图标、亚克力效果、开机启动这些 Windows 专属功能，需要你第一次运行时帮忙确认。

已知限制：

- 扫描件 PDF（只有图片没有文字层）搜不到正文，需要 OCR；
- 旧版 `.doc`/`.xls`/`.ppt` 二进制格式只索引文件名；
- 尚未支持微软商店应用（UWP，如「设置」「计算器」），只支持开始菜单里的快捷方式；
- 不支持拼音搜索。

## 9. 后续路线

1. **直接读 MFT**：第一次建索引和「重新扫描」现在要逐个文件夹列目录（全盘约 45 秒）；直接读 NTFS 主文件表可以缩短到几秒，但需要管理员权限（一个以系统权限运行的小服务）。
2. **OCR**：用 Windows 自带的 `Windows.Media.Ocr` 识别扫描件 PDF 和图片里的文字，空闲且接电源时进行。
3. **拼音与首字母**：`wx` 找到「微信」、`hetong` 找到「合同」。
4. **UWP 应用、系统设置项、浏览器书签**等更多结果来源。
5. **查询语法**：`kind:pdf`、`date:本周`、`in:文档` 等过滤条件。
6. **更丰富的预览**：PDF 首页缩略图、图片预览。
